# KinetixFitt — Auditoría y mejoras 2026-09-16

## Alcance
Revisión del estado actual de `develop` y aplicación de correcciones directamente sobre el repositorio. El código continúa siendo la fuente de verdad.

## Cambios aplicados

- **Branding global:** metadata de Next.js y manifest PWA migrados de `EZEQUIEL COACHING` a `KinetixFitt`.
- **PWA:** eliminado del manifest el bloque de screenshots que apuntaba a assets no presentes en `public/icons/`.
- **SEO técnico:** añadidos `src/app/robots.ts` y `src/app/sitemap.ts`; las rutas privadas y API quedan fuera del crawling.
- **CSP/security headers:** corregido el matcher de `next.config.mjs`; contenía un espacio final que podía impedir el matching esperado de rutas normales.
- **CI:** la suite `test` ahora incluye voice y security además de stats/core/domain.
- **CI/Postgres:** añadido health check nativo al servicio Postgres y eliminado el loop manual de espera.
- **Electron:** identidad de paquete actualizada a `com.kinetixfitt.app` / `KinetixFitt`.
- **Capacitor:** identidad actualizada a `com.kinetixfitt.app` / `KinetixFitt` y URL configurable mediante `CAPACITOR_SERVER_URL`.
- **Auth:** login usa `getClientIp()` para respetar la política de proxy confiable y deja de devolver mensajes internos de Zod/DB al cliente.

## Verificación

- Cada modificación fue committeada en `develop` con Conventional Commits.
- CI se dispara automáticamente por push a `develop`; el último run observado estaba ejecutándose al cierre de esta revisión.
- No se afirma que build/E2E local o packaging nativo hayan sido verificados desde un dispositivo físico en esta sesión.

## Próximos riesgos reales a resolver

1. Unificar completamente el branding residual en documentación y textos internos.
2. Verificar journeys E2E completos: registro → onboarding → asignación → workout → progreso → mensajería → pagos.
3. Resolver ownership en **todas** las rutas que aceptan `clientId`, no solo analytics.
4. Migrar rate limiting de memoria a Redis/KV cuando haya despliegue multi-instancia.
5. Implementar rotación/revocación robusta de sesiones y recuperación de contraseña persistente.
6. Consolidar timers y nutrición para eliminar duplicación funcional.
7. Verificar Capacitor y Electron end-to-end en builds reales.
8. Revisar el `DIRECT_URL` de Prisma para producción; no debe apuntar al pooler si el proveedor requiere conexión directa para operaciones administrativas.
9. Mantener un solo `package-lock.json` en la raíz; no reintroducir locks por workspace.
